# MOTION — локальный захват движения

Камера на весь экран с подробным трекингом: тело (33 точки), две кисти (по 21), лицо и радужки (478). Максимум 553 точки. Без панелей и установки программ для пользователя. Все модели работают в браузере; камера и её кадры не отправляются на сервер.

## Запуск

Требуется Node.js 22.12+ (проверено на 24).

```sh
npm ci
npm run setup
npm run dev -- --port 5173
```

Откройте **http://localhost:5173/** и разрешите камеру. При первом запуске GPU может несколько секунд компилировать модели; изображение камеры видно сразу, геометрия появится после прогрева. Покажите ладонь крупным планом или отойдите, чтобы захватить тело: поверх тела сама включается 3D-сетка — хоть на всё тело, хоть по пояс, хоть на голову с плечами у ноутбука (см. ниже, нужен `npm run setup:dense`). Для камеры нужен localhost или HTTPS; если встроенный браузер не запрашивает доступ, используйте Chrome/Safari.

`setup` скачивает модели фиксированной версии, проверяет SHA-256 и копирует WASM из закреплённого пакета. При неполной загрузке файл не устанавливается. После setup внешние CDN и интернет для инференса не нужны.

```sh
npm test
npm run build
npm run preview -- --port 5173
```

`dist/` готов к обычному статическому хостингу по HTTPS в корне сайта. Подкаталог URL пока не поддерживается. Приложение запускает камеру только локально, деплой сам по себе камеры не получает.

`npm run build` после Vite режет каждый файл больше 24 МиБ на части по 20 МиБ (`*.part0…` + `*.parts.json` с SHA-256): веса сетки, runtime ONNX и `pose_heavy.task`. Браузер сам склеивает и проверяет части, поэтому сборка проходит лимиты статических хостингов (Cloudflare Pages — 25 МиБ на файл, GitHub предупреждает с 50 МБ). Весь `dist/` — около 190 МБ, из них ~115 МБ — сетка; обычный скелет грузит около 33 МБ.

## Что реализовано

- Три модели в независимых Web Worker: Pose Full, Face Landmarker и Hand Landmarker. Один coordinator собирает результаты **одного и того же кадра**.
- Модели находят лицо и кисти даже без полного тела в кадре.
- Исходный кадр возвращается вместе с координатами. Камера и скелет совпадают по времени, очередь старых кадров не накапливается.
- Захват запускается по новым декодированным кадрам камеры, а не по изменению часов видео. Тестовые ролики начинают обрабатываться с нулевого кадра после прогрева моделей.
- Лицо: плотная сетка, контуры губ, век, бровей, лица и радужек. Кисти: все суставы пальцев. Грубые лицевые линии и псевдопальцы Pose исключены из отрисовки.
- Адаптивное сглаживание с ограничением добавленного смещения, стабильные ID кистей, сброс при потере и возвращении детекции.
- Контроль видимости тела и согласованности моделей, включая найденный на настоящем видео ложный скелет внутри кисти.
- GPU → CPU fallback, таймауты, отмена запуска, повторный запуск, освобождение камеры/bitmap/worker.
- Данные лица также включают 52 blendshape-коэффициента и матрицу положения лица для дальнейших сценариев.

Full выбран по результатам сравнительных тестов. Heavy здесь не оказался универсально точнее. Явные варианты: `/?model=heavy` и `/?model=lite`.

## Поверхность тела (3D-сетка)

Скелет, лицо и пальцы дополняются трёхмерной анатомической сеткой **InstantHMR → MHR**. Реконструкция содержит 4 899 вершин и 127 узлов rig. Для отображения исключены голова и кисти — их точнее ведут специализированные модели: остаётся до 2 056 вершин и 4 068 треугольников. Это вершины предсказанной поверхности, а не тысячи независимо измеренных суставов.

```sh
npm run setup:dense
npm run dev -- --port 5173
```

Как работает:

- **Включается сама**, когда тела достаточно не меньше 150 мс: полное тело (плечи, таз, колени, щиколотки), верх тела — плечи вместе с тазом или с локтями, или крупный план у ноутбука — голова и плечи, а тело уходит за нижний край кадра (тут нужно найденное лицо на месте головы). Ноги не нужны: если тело обрезано нижним краем кадра, сетка идёт до края; если низ скрыт в кадре (например, столом), сетка плавно гаснет чуть ниже самого нижнего видимого сустава и не рисует угаданные ноги поверх стола.
- Сетка привязывается к точкам Pose: плечам, глазам, ушам и носу, а видимые сегменты рук и ног подгоняются по отдельности (плечо→локоть без кисти тоже). Голова и кисти не рисуются сеткой — их ведут свои модели, — но заслоняют то, что за ними (шея не лезет на подбородок).
- Короткое перекрытие её не гасит; выключается, если плечи пропали на 0,45 с или тела недостаточно дольше 1,2 с. На одной ладони в кадре сетка не включается: межмодельная проверка отсекает ложные тела внутри кисти до этого решения, а для верха тела, если найденная кисть накрывает оба плеча, дополнительно нужно лицо на месте головы.
- **Не тормозит скелет.** Камера и 553 точки идут с частотой камеры сразу; файлы сетки (~115 МБ: веса, runtime ONNX, rig MHR) грузятся в фоне после старта камеры и кешируются в браузере (Cache API), повторное открытие — без скачивания.
- Нейросеть работает в отдельном воркере на WebGPU по кропу 224×224, который вырезает и масштабирует GPU; она запускается не чаще раза в 66 мс и держит GPU занятым не больше чем наполовину (~7 раз/с на M1 Pro). Второй воркер на **каждом** кадре подгоняет rig MHR к сглаженным точкам Pose (старт с предыдущего кадра, 1€-фильтр предсказаний сети), поэтому сетка идёт вместе с телом на 30 fps; кадр ждёт свою подгонку не дольше 24 мс.
- Без WebGPU с `shader-f16` сетка просто не включается, скелет работает как обычно. `?surface=0` отключает сетку, `?surface=1` включает её принудительно, в том числе медленно на CPU (~0,4 с на кадр сети). При включённом «Экономии трафика» сетка по умолчанию не грузится.

Замеры на MacBook Pro M1 Pro, Chrome, виртуальная камера 1280×720 из тестового видео приседаний, 20 с:

| | Кадров скелета/с | Нагрузка CPU (ядер, весь Chrome) |
| --- | ---: | ---: |
| Только скелет | 30 | 0,76 |
| Сетка, прежняя версия (`?surface=1`) | 13,7 | 1,14 |
| Сетка, текущая версия | 30 | 1,11 |

Контур одежды, скрытые части и точная глубина не измеряются. На небольшом размеченном наборе коррекция улучшила исходную проекцию MHR, но не превзошла обычный Pose по точности суставов. Полные метрики и ограничения: [проверка поверхности](docs/dense-validation.md).

`npm run test:dense` сам запускает временный сервер, проигрывает реальные ролики и закрывает браузер/сервер в `finally`; `DENSE_TEST_BUILT=1` проверяет собранный `dist/` с разрезанными файлами. Перед ним подготовьте обычные fixtures; путь можно передать через `CAPTURE_FIXTURES_DIR`. Сам тест камеру не открывает. `node scripts/setup-dense.mjs --check` проверяет закреплённые веса и runtime без скачиваний.

## API для дальнейшей разработки

На странице доступен локальный интерфейс. Он не отправляет данные по сети и не записывает видео.

```js
const unsubscribe = motionCapture.subscribe(frame => {
  // frame.pose.landmarks / worldLandmarks
  // frame.face.landmarks / blendshapes / transformationMatrix
  // frame.hands[i].landmarks / worldLandmarks / track.id
  // frame.timestamp, receivedAt, sourceFrameId, mediaTime, sourceWidth, sourceHeight, timings
  // frame.fusion — причины отклонения противоречивых результатов моделей
  // frame.bodySurface — inferred vertices/faces/skeleton/camera while the surface is on (else null; read-only)
  // frame.surface — surface state: active, fullBody, missingJoints, fit, inference timings
  // point.drawConfidence === 0 → пропустить точку
});

motionCapture.getDiagnostics();
motionCapture.stop();
await motionCapture.start();
// await motionCapture.start({surface: false}); // без сетки; true — принудительно, 'auto' — по умолчанию
unsubscribe();
```

`pose` и `face` могут быть `null`; руки — пустым массивом. Координаты изображения не отражены; зеркальность применяется только при отображении. World-системы кисти и тела имеют разные начала. `frame.source` принадлежит сессии; подписчику нельзя закрывать или сохранять этот bitmap между кадрами. Для собственной копии используйте `createImageBitmap(frame.source)` и закройте копию после работы. `stop()` останавливает и явно переданный через `start({stream})` поток.

Для тестового видео: `start({videoUrl:'/path/video.mp4'})` или `/?video=/path/video.mp4`. Только same-origin/локальный blob URL. В режиме `/?test=1` камера автоматически не запускается.

## Проверка

`npm test` запускает проверки геометрии, временных фильтров, перекрытий, повторного захвата, идентификаторов кистей и регрессий. Браузерный прогон **исполняет настоящие ML-модели** на пяти видеороликах; также проверяет остановку, замену потока, потерю человека и ошибки доступа. Дополнительный локальный крупный план можно передать через переменную окружения.

```sh
# Playwright установлен через npm ci; нужен Chrome или Chromium.
node scripts/fixtures.mjs --ffmpeg /absolute/path/to/ffmpeg
npm run test:browser
npm run test:soak
```

Подготовка медиа и результаты: [документация тестирования](docs/testing.md). Обоснование выбранной архитектуры: [совместное ревью](docs/architecture.md).

## Практические ограничения

Одна камера не измеряет точную 3D-поверхность и скрытые конечности. При перекрытиях, маленьком лице, смазывании и плохом освещении возможны ошибки. Если очень близкая ладонь закрывает всю голову и оба плеча, модуль может временно скрыть тело, даже когда видны ноги: такой кадр неоднозначен. Ирис отслеживается, но точка взгляда на экране не калибрована. Углы/глубина приблизительные. Это модуль захвата, а не медицинская оценка и ещё не законченный конкурсный сценарий.

## Происхождение

Основная логика написана 28–29 сентября 2026 после старта хакатона. Старый `Oryntai/handstick` обсуждался как опыт команды; исходники из него не копировались. Базовые обученные модели — Google MediaPipe. Опциональная поверхность использует закреплённые InstantHMR, MHR и ONNX Runtime Web 1.30.0. Команда написала синхронизацию, управление жизненным циклом, стабилизацию, межмодельные проверки, браузерный порт MHR, ограниченную коррекцию проекции, визуализацию и тесты. Собственного обучения модели не проводилось. Источники, изменения и лицензии: [MHR/Momentum](public/dense/NOTICE.md), [InstantHMR weights](public/dense/weights-NOTICE.md).
