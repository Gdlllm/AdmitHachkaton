# Проверка захвата

Тесты исполняют настоящие локальные модели. ML-вывод не заменяется искусственными координатами. Синтетические последовательности используются отдельно в unit-тестах временного фильтра и обозначены как синтетические.

Два WMV-файла перекодируются в H.264 MP4 с помощью FFmpeg. Исходники закреплены commit SHA и проверяются SHA-256. Приватный кадр пользователя использован только локально, в набор для распространения не входит. Отдельный тест двух кистей использует зеркальные копии настоящего клипа: это составной тестовый вход, не видео человека с двумя руками.

## Воспроизведение

```sh
npm ci
npm run setup
node scripts/fixtures.mjs --ffmpeg /absolute/path/to/ffmpeg
npm run dev -- --port 5173
# в другом терминале:
npm test
npm run test:browser
npm run test:soak
npm run test:transition
```

Для автоматизации нужен Playwright. Если локальный Chrome не найден: `npx playwright install chromium`. Можно явно задать `CAPTURE_CHROME_PATH`, `PLAYWRIGHT_MODULE`, `CAPTURE_BASE_URL` и `CAPTURE_FIXTURES_DIR`. Скрипт fixtures принимает `--out /path`; браузерный тест ищет по умолчанию `tests/fixtures`.

Дополнительное локальное изображение: `CAPTURE_CLOSEUP_IMAGE=/absolute/path/to/image.png npm run test:browser`. Кадры обрабатываются в тестовом браузере, не отправляются внешнему сервису. Скриншоты и JSON находятся в `tests/artifacts/`; эта папка и тестовые медиа исключены из Git.

## Интеграционные прогоны 28–29 сентября 2026

Среда: macOS, Apple M1 Pro, Chrome 153, WebGL через ANGLE Metal. Это одна проверенная конфигурация, не обещание такой же скорости на каждом устройстве.

17 из 17 сценариев браузерной проверки прошли, непойманных ошибок страницы нет. Счётчики ниже описывают **проверенные кадры**, не процент точности модели. Этот прогон перематывает ролики к нескольким позициям и проверяет повторное обнаружение; непрерывное воспроизведение проверено отдельно ниже.

| Сценарий | Наблюдение |
|---|---|
| Движения тела | Pose в 22/22 проверенных кадрах |
| Приседания | Pose в 20/20; обе кисти в 5 кадрах |
| Только кисть | Hand в 21/21; ложных Pose и Face нет |
| Повороты головы | Face в 17/18; один пропуск в проверке с перемотками |
| Освещение лица | Face в 18/18 |
| Локальный крупный план с ладонью | Face 478 + Hand 21 в 8/8 |
| Две составленные кисти | 21 + 21 в 10/10; разные ID |
| Человек исчезает | Пустые кадры удаляют старую геометрию |
| Жизненный цикл | Stop, отмена запуска, смена источника, pagehide, ошибка источника, stop из callback |
| Ресурсы | CDP видит 4 настоящих worker в работе и 0 после остановки; camera tracks остановлены |

Отдельная браузерная регрессия подтверждает: `stop()` завершает ожидающий `start()` до ответа на запрос доступа к камере; поздно полученный поток сразу останавливается.

Production-сборка также проверена по автоматическому пути `getUserMedia` без `?test=1`: Chrome получил записанное публичное видео как виртуальную камеру через тестовый параметр `--use-file-for-fake-video-capture`. Приложение обработало 240 кадров, показало тело и сохранило интерфейс без текста и панелей. Все запросы остались на локальном origin; после остановки camera track перешёл в `ended`, worker-контексты — с 4 до 0, исключений страницы нет. Это проверка браузерного интерфейса камеры, не утверждение о проверке физической веб-камеры. Отчёт — `tests/artifacts/production-report.json`.

При финальном открытии физической камеры во встроенном браузере получен `NotReadableError` (интерфейс показывает «Камера занята»); повторная попытка дала тот же результат. Работа с живой физической камерой в этой сессии не подтверждена. Нужен повторный запуск после освобождения камеры либо проверка в Chrome.

## Непрерывное воспроизведение всех роликов

Финальный прогон production-сборки исполнил 880 разных кадров от начала до конца пяти роликов, суммарно 55,1 секунды исходного видео. Для каждого ролика первый результат относится к `mediaTime=0`; `mediaTime` и `sourceFrameId` строго возрастают. Скрипт не перематывает видео и не ограничивает число кадров. Повторная обработка того же декодированного кадра запрещена проверкой.

| Ролик | Обработано / кадров источника | Детекции целевого региона | Медиана задержки после прогрева | 95-й процентиль |
|---|---:|---|---:|---:|
| Движения тела, 30 FPS | 120 / 120 | Pose 120/120 | 23,6 мс | 29,7 мс |
| Приседания, 5 FPS | 64 / 65 | Pose 64/64; две кисти в 14 кадрах | 60,1 мс | 68,0 мс |
| Жесты кисти, 25 FPS | 319 / 325 | Hand 319/319; ложные Pose и Face: 0 | 37,3 мс | 46,2 мс |
| Повороты головы, 15 FPS | 288 / 288 | Face 288/288 | 31,7 мс | 37,7 мс |
| Освещение лица, 15 FPS | 89 / 89 | Face 89/89 | 31,3 мс | 37,6 мс |

Задержка измерена от захвата bitmap до получения результата в основном потоке. Это не полная задержка от физического движения до экрана. Первый кадр с прогревом занимал 490–599 мс. Приседания в исходнике имеют частоту 5 FPS; низкая частота результатов в этом тесте не означает предел вычислительной скорости. Один кадр этого ролика пропущен декодером; в ролике кисти шесть промежуточных кадров не попали в инференс при занятости моделей.

Непойманных ошибок страницы: 0. После каждой остановки CDP подтвердил 0 оставшихся worker-контекстов вместо 4 активных. Максимальное добавленное сглаживанием смещение осталось в пределах 4 пикселей тела / 3 кисти / 2 лица. Это предел фильтра, а не точность модели.

ID кистей — временные пространственные треки. В приседаниях отмечен сброс первых ID после интервала при прогреве, превышающего срок хранения 650 мс. Ещё три сигнала возможного переключения ID совпали с попеременным обнаружением одной кисти при 5 FPS; без разметки нельзя подтвердить ошибку идентичности. Долговременное узнавание руки после перекрытия не заявляется.

Первый непрерывный прогон выявил 26 кадров с ложным телом и один с ложным лицом внутри ладони. Добавлены межмодельная проверка и сохранённые геометрические регрессии; повторный полный прогон не воспроизвёл эти ошибки. Другой найденный дефект — счётчик принимал изменение часов видео за новый кадр — исправлен через уведомления декодера. Старые числа вызовов модели не используются как FPS.

Машинный отчёт: `tests/artifacts/soak-report.json`, создаётся `npm run test:soak`. Проверка не имеет ручной разметки и не утверждает, что каждая найденная координата верна.

## Удерживаемый жест и переключение сцен

Дополнительный тест увеличенной кисти обнаружил ложное лицо, которое выходило за прямоугольник суставных точек на 20,6 пикселя. На неподвижном повторе кадра модель возвращала ложное лицо в 20 из 30 кадров, в том числе последовательными парами. Поэтому ожидание двух обнаружений не устраняет эту ошибку. Использование уже существующей физической области кисти вместе с проверкой центра ладони дало 0 ложных лиц в 30 кадрах, сохранив кисть в 30/30. Реальный локальный крупный план лица с поднятой ладонью после исправления сохранил оба региона в 30/30 кадрах.

`npm run test:transition` проверяет последовательность «увеличенная кисть → тело → лицо → пустой кадр» внутри одного потока 1280×720, без перезапуска моделей и смены разрешения. Цветовая метка в исходном bitmap относит каждый результат к правильной сцене, даже если предыдущий кадр ещё обрабатывается. В фазе кисти ложные Face/Pose теперь приводят к падению теста с сохранением исходного кадра и сырых координат. Это составной диагностический вход из настоящих видео, а не запись такого перехода одной камерой.

Финальный переходный прогон: кисть 24/24, ложные Pose/Face — 0; тело появилось на втором кадре (около 164 мс), лицо на первом (55 мс), пустой источник удалил всю геометрию с первого кадра (63 мс). Между сценами сохранились одна сессия и те же четыре worker; после остановки осталось 0. Первый отсчёт появления кисти включает прогрев моделей и не сравнивается со скоростью переходов. Полный отчёт — `tests/artifacts/transition-report.json`.

Этот тест также выявил ошибку подсчёта перекрытия тела: восемь грубых лицевых точек Pose находились вне кисти, хотя все семь видимых суставов тела лежали внутри. Проверка теперь использует тот же набор суставов, который рисуется как тело; независимо видимая голова и конечности вне кисти защищены отрицательным тестом. Пороги расширения границы и доли перекрытия не увеличивались.

Повторный полный прогон выявил другое семейство ошибок: голова и плечи ложного тела находятся внутри кулака, а ноги дорисованы вдоль предплечья, до 345 пикселей за пределами кисти. Расширять границу кисти на такое расстояние нельзя. Дополнительная проверка требует совпадения всех 13 точек головы и плеч с исходным прямоугольником одной кисти и отсутствия независимого подтверждения лица. Сценарии «закрыта только голова, плечи видны», «настоящее лицо видно между пальцами», «другое лицо находится в стороне» и неоднозначное полное перекрытие проверяются отдельно. Постоянный набор содержит 36 измеренных ошибочных результатов; всего проходят 55 unit-тестов геометрии, фильтров, отображения и жизненного цикла.

## Сравнение архитектур

Независимый сравнительный прогон на тех же видеокадрах, время обработки, медиана:

| Ролик | Последовательно Heavy | Параллельно Heavy | Параллельно Full |
|---|---:|---:|---:|
| Движения тела | 43,2 мс | 39,7 мс | 21,4 мс |
| Приседания | 48,0 мс | 47,7 мс | 29,3 мс |
| Кисть | 48,6 мс | 47,9 мс | 38,4 мс |

В этих трёх роликах Face не срабатывал: таблица не представляет максимальную одновременную нагрузку всех регионов. У последовательного и параллельного Heavy на 54 кадрах совпали все 2829 проверенных векторов координат. Это проверка эквивалентности, не оценка точности относительно ручной разметки.

Тяжёлая модель дала ложное тело внутри ладони с высокой confidence. Этот факт и выигрыш времени определили выбор Full. Добавлен тест межмодельного подавления именно такой ошибки.

## Что числа не доказывают

Для утверждения о точности в миллиметрах, гарантированном трекинге всех перекрытий или сравнении качества на популяции нужны размеченные данные и отдельная оценка. Здесь проверены работоспособность, конкретные регрессии, согласованность кадров, ограничение сглаживания и задержка на данной машине. Synthetic jitter benchmark относится только к фильтру; он не превращает приблизительные координаты модели в точное измерение.
